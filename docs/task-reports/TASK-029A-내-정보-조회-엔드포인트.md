# TASK-029A. 내 정보 조회 엔드포인트 (GET /auth/me)

## 상태
완료

## 날짜
2026-10-21

## 작업 요약
T027에서 만들어 둔 "건물 입구 검사대"(`get_current_user` 의존성)를 드디어 실제 방(라우트) 앞에 설치하는 Task입니다. `GET /api/v1/auth/me`는 "지금 로그인한 사람이 누구인지" 묻는 가장 단순한 엔드포인트라서, 검사대만 통과하면(=`Depends(get_current_user)`) 그 사람 정보를 그대로 돌려주면 끝 — 라우트 본문이 `return current_user` 한 줄입니다. 쿠키가 없거나, 가짜거나, 만료됐거나, access/refresh 토큰을 헷갈려 보냈거나, 토큰은 유효한데 사용자가 DB에 없는 경우 모두 T027에서 이미 401로 통일 처리하도록 만들어 뒀기 때문에, 이번 Task에서는 그 처리를 다시 만들 필요가 전혀 없었습니다.

## 기술 결정 (해당 시)
- T027의 `test_dependencies.py`가 이미 증명한 5가지 실패 케이스 중 3가지(쿠키 없음/가짜 토큰/타입 혼동)를 **실제 `/me` 라우트를 통해서도** 다시 검증 — 의존성 자체는 이미 검증됐지만, "라우트에 실제로 연결됐는지"는 또 다른 검증 대상이기 때문에(예: 연결을 깜빡하거나 다른 의존성을 잘못 끼워 넣는 실수) 중복이 아니라 별도의 보장.
- 유령 사용자(토큰은 유효하지만 DB에 사용자가 없는 경우) 케이스는 `test_dependencies.py`에서 이미 충분히 검증됐고 DB에서 사용자를 지우는 과정이 복잡하므로 라우트 테스트에서는 생략 — 의존성 레벨 테스트로 커버리지가 충분하다고 판단.
