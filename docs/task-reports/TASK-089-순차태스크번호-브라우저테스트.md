# TASK-089. 수동 브라우저 테스트: 태스크 3개 연속 생성 → 번호 1, 2, 3 확인

## 상태
완료 (PASS)

## 날짜
2026-10-22

## 작업 요약
동일 프로젝트에서 서로 다른 업로드 방식(파일/폴더/붙여넣기)으로 태스크 3개를 연속 생성해 `task_number`가 1, 2, 3 순으로 매겨지는지 검증했다 — T084(파일 업로드)·T085(폴더 업로드)·T086(코드 붙여넣기)을 같은 세션에서 순서대로 수행한 것이 그대로 이 시나리오를 구성했다.

**결과**: 태스크 타임라인에 "Task 1"(단일 파일 업로드 테스트) → "Task 2"(폴더 업로드 테스트) → "Task 3"(코드 붙여넣기 테스트) 순으로 정확히 표시됨 — PASS. `TaskService.create`(T068)의 "프로젝트 내 기존 최대 task_number + 1" 로직이 업로드 방식과 무관하게 올바르게 증가함을 확인했다.

또한 T087(11MB 거부)·T088(바이너리 거부)처럼 **검증에 실패한 시도는 task_number를 소비하지 않는다**는 것도 함께 확인했다 — 두 번의 실패한 제출 이후에도 목록은 여전히 Task 1~3뿐이었다(Task 4로 건너뛰지 않음).
