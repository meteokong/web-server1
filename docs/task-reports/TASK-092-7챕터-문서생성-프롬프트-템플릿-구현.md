## 작업 요약
`backend/src/services/ai/prompts.py`에 7챕터 학습 문서 생성용 프롬프트 템플릿을 구현했다. `SYSTEM_INSTRUCTION`은 research.md의 "You are an expert teacher explaining code to complete beginners with zero programming knowledge" 지침에 FR-035/036/037(초보자 대상, 전문 용어 금지, 실생활 비유 필수)을 명시적으로 덧붙였다. `build_document_generation_prompt(*, files, language=None, complexity_level=None)`는 spec.md FR-026~FR-034의 챕터별 요구사항(챕터2 개념 카드 최대 5개, 챕터7 실수 사례 3~5개 등)과 data-model.md `content` JSONB 구조(chapter1~chapter7)를 그대로 지시문으로 변환해, Gemini의 JSON 모드(`response_mime_type="application/json"`, T091)로 보낼 사용자 프롬프트를 생성한다. 코드 파일은 `CodeFileInput(file_name, content)` dataclass로 표현해, DocumentGenerationService(T093)가 파일시스템에서 읽은 코드 내용을 그대로 넘기면 되도록 했다.

## 기술 결정
- 프롬프트 모듈은 순수 문자열 생성만 담당하고 파일시스템/DB/네트워크를 전혀 건드리지 않도록 분리 — `CodeFile`(T009 모델)은 메타데이터만 갖고 있고 실제 내용은 `storage_path`에서 읽어야 하므로, 그 책임은 DocumentGenerationService(T093)에 남겨둠.
- 챕터별 세부 스키마(필드명)는 data-model.md 예시 JSON을 기반으로 정의했지만, 챕터4(`explanations`)·챕터5(`steps`)·챕터6(`concepts`)의 필드명은 data-model.md에 `[...]`로만 표시되어 있어 spec.md FR-031/032/033의 서술(무엇을 하는지/문법 분해/비유/대안 예시/주의사항, 단계별 설명, 무엇/왜/어디서 쓰이는지)을 참고해 직접 설계함 — 추후 실제 생성 결과를 보고 조정 가능.
- `response_schema`(SDK의 엄격한 JSON 스키마 강제)는 사용하지 않고 프롬프트 지시문 + `response_mime_type="application/json"`(유효한 JSON 보장)만으로 구조를 유도 — T091의 `GeminiClient.generate_content`가 이미 그렇게 설계되어 있고, 엄격한 schema는 스키마와 프롬프트 두 곳을 동시에 유지보수해야 해서 과설계로 판단.
